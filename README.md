# Цифровая шахта «Болашақ»: противоаварийная защита на OpenEgiz

Цифровой двойник подземной хромовой шахты «Болашақ» Донского ГОКа (Хромтау, Актюбинская область, АО «ТНК «Казхром»). Двойник считает вентиляционную сеть, распространение пожара и дыма, движение техники, руды и людей. Модуль ПАЗ отрабатывает позиции плана ликвидации аварий (ПЛА): закрывает клапаны и двери, снимает напряжение, включает водяные завесы, реверсирует вентилятор, выводит людей. Советчик диспетчера за секунды прогоняет 30 минут аварии вперёд для каждого режима проветривания и проверяет, правильно ли составлен ПЛА.

Концепция, состав двойников, модули, сценарии и источники данных описаны в [SUBMISSION.md](SUBMISSION.md), презентация — [presentation.pdf](presentation.pdf).

## Запуск

Требования: Ubuntu 24.04 (или WSL2), Docker с Compose v2, `make`, свободные порты 3000, 8080, 8085, 8086, 8090, 8095, 1883. Подробнее о платформе — в [OPENEGIZ.ru.md](OPENEGIZ.ru.md).

```bash
command -v make >/dev/null || sudo apt-get install -y make
make up
make mine-check
```

Первая строка ставит `make`, только если его нет (на чистой Ubuntu его нет). `make up` поднимает платформу OpenEgiz и всю шахту: двойники, симулятор, ПАЗ, советчик, интерфейс, дашборд. `make mine-check` проверяет решение от начала до конца: прогоняет аварийный сценарий, проверяет сброс в норму и сравнение режимов защиты на стенде (около минуты).

`make up` при первом запуске генерирует пароли в `deploy/compose/.env`, собирает образы решения (Python-сервисы и веб-интерфейс), создаёт двойников в Ditto и запускает симулятор. Первый запуск занимает 5–10 минут, GPU и внешние датасеты не нужны. В конце команда печатает адреса и логины.

Остановить: `make down`. Удалить всё вместе с данными: `make clean`.

### Доступ с другого компьютера

Все порты по умолчанию слушают только `127.0.0.1`: пульт и Grafana открываются в браузере на той же машине, где выполнен `make up`. Чтобы открыть их с другого компьютера, удобнее всего SSH-туннель — он ничего не открывает в сеть:

```bash
ssh -L 8095:localhost:8095 -L 3000:localhost:3000 user@адрес-сервера
```

После этого пульт доступен на своём компьютере по http://localhost:8095. Второй способ — открыть порты в локальной сети: в `deploy/compose/.env` задать `OPENEGIZ_BIND=0.0.0.0` и `OPENEGIZ_PUBLIC_HOST=<адрес сервера>`, затем снова `make up`. MQTT и расширенный API платформы работают без пароля, поэтому так стоит делать только в доверенной сети.

## Что открыть

| Адрес | Что там |
|---|---|
| http://localhost:8095 | Пульт диспетчера шахты: 3D-модель выработок с дымом, людьми и техникой, мнемосхема горизонтов, вкладки «Обстановка», «ПАЗ», «Советчик», «Сценарии», «Журнал». Клик по объекту открывает его карточку и ручное управление |
| http://localhost:3000/d/bolashak-mine | Дашборд Grafana «Шахта «Болашак»»: люди, выдача руды, CO и видимость на газоаналитических узлах, мощность пожара, ГВУ, пожарный трубопровод. Логин `admin`, пароль печатает `make up` |
| http://localhost:3000 → приложение OpenEgiz → Twins | Все двойники шахты в namespace `bolashak` с иерархией `_parents` |

## Как запустить сценарий

1. Откройте пульт http://localhost:8095, вкладка «Сценарии».
2. Выберите аварию (пожар ПДМ, самосвала, зарядной камеры, конвейера, склада ГСМ, ЦПП или остановку вентилятора) и при желании отказы защиты: заклинившую дверь, несработавший клапан, отказ датчика, отказ бортовой системы пожаротушения техники, низкое давление воды, неисправный клетевой подъём.
3. Нажмите «Запустить сценарий». ПАЗ обнаружит пожар по датчикам и выполнит позицию ПЛА, советчик выдаст прогноз и рекомендацию, люди пойдут к убежищам и стволу.
4. «Сброс в норму» возвращает шахту в штатный режим. На вкладке «ПАЗ» автоматику можно переключить в ручной режим или вывести из работы, чтобы сравнить исходы.

Сценарий «Пожар ПДМ при отказе бортовой системы и датчика участка» показывает аварию, в которой люди действительно попадают в дым: защита узнаёт о пожаре слишком поздно. Сценарий «Пожар склада ГСМ при отказе датчика склада» показывает, как советчик уточняет позицию ПАЗ. Подробности — в разделе «Сценарии» [SUBMISSION.md](SUBMISSION.md).

Сценарии запускаются через двойник `bolashak:control` (desiredProperties признака `scenario`), без изменения кода. Сравнение «автоматика / диспетчер / без ПАЗ» на одном и том же сценарии считает стенд советчика (desiredProperties признака `study`), результат приходит в признак `study` двойника `bolashak:advisor`.

|---|---|
